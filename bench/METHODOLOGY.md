# Benchmark methodology

## Scope and reproducibility

This benchmark reports deterministic detector performance separately from optional model utility. Run it from the repository root:

```bash
python bench/generate_synthetic.py
python bench/run_benchmark.py
```

The harness commits raw output under `bench/results/`. It records the Python version, platform, data source status, detector metrics and latency distribution. It does not call a hosted service, and benchmark output should be regenerated on the target machine before making claims about its performance.

## Datasets and licensing

### Synthetic fixtures (always available)

`bench/data/synthetic.jsonl` is generated by `bench/generate_synthetic.py`. It contains fictional, test-only values such as `example.test` email addresses, documentation IP ranges, a sandbox payment-card number, a synthetic checksum-valid Aadhaar-shaped number, fake bank/payment identifiers and well-known dummy credential patterns. Gold annotations are exact character offsets. This set is intentionally small and diagnostic; it is not representative of production data distribution.

### Ai4Privacy OpenPII Nano (optional public source)

The optional public sample is [`ai4privacy/pii-masking-nano-1k`](https://huggingface.co/datasets/ai4privacy/pii-masking-nano-1k), validation split. Its Hugging Face dataset card identifies the license as **CC-BY-4.0**, describes 990 synthetic examples in total (900 training and 90 validation rows), with 19 labels, 30 languages, 37 regions and 7,611 annotations, and says the sample contains synthetic PII rather than real personal data. Attribution is required; users must comply with CC-BY-4.0. The raw dataset is not committed to this repository. Fetch and normalize it with:

```bash
pip install '.[bench]'
python bench/fetch_openpii.py
python bench/run_benchmark.py
```

The adapter evaluates only three label mappings with corresponding VeilRelay entity types: `EMAIL`, `TELEPHONENUM` → `PHONE`, and `CREDITCARDNUMBER` → `CREDIT_CARD`. Social-number labels are intentionally excluded because they do not map cleanly to a single supported identifier validator. All other gold labels are excluded from these mapped entity metrics rather than silently relabeled. The dataset card should be rechecked before every publication because repository content and terms can change.

## Compared systems

- **VeilRelay**: built-in regex/checksum PII detector plus provider-secret detector, default policy settings, no NER model.
- **Plain regex**: intentionally simple baseline for email, phone, IPv4, credit-card-shaped digits, US SSN-shaped values, AWS-key-shaped values and generic `sk-` keys. It does not use checksums or locale-specific validators.
- **Microsoft Presidio**: `AnalyzerEngine()` default recognizers and default settings, when the optional `presidio-analyzer` dependency and its runtime requirements are available. No custom recognizers are added. Entity results are limited to the explicitly mapped labels documented in the source.

A skipped comparator is recorded as skipped; it is not assigned zero precision or recall. The CSV contains rows only for comparators that actually ran.

## Detection quality

Gold and predicted entities are matched by exact `(start, end, entity_type)` tuple. A predicted entity with the right value but a different boundary or type is counted as a false positive and the gold entity as a false negative. Precision, recall and F1 are computed per entity type. This strict matching avoids partial-credit ambiguity but penalizes boundary differences.

## Latency

The harness measures only local detector execution, not network/upstream latency. It performs 10 measurements per example for the plain-regex baseline and VeilRelay, with `time.perf_counter_ns()`. The reported added latency distribution is the per-run difference `VeilRelay elapsed - plain regex elapsed`. p50 and p95 use linearly interpolated empirical percentiles. Results are hardware-, interpreter-, load- and dataset-dependent; raw numbers are descriptive, not universal claims.

## Utility preservation

Three deterministic task templates cover summarization, extraction and question answering. With `OLLAMA_MODEL` configured, the harness sends each original and VeilRelay-redacted prompt to the local Ollama `/api/chat` endpoint. For redacted prompts, the harness restores known placeholders in the model response before scoring. It scores answers by the fraction of task-specific expected terms appearing exactly (case-insensitively) in the user-visible answer. It commits only score/count metadata, never model answers or matched terms. This is a deliberately simple rubric, not a semantic judge. `OLLAMA_HOST` defaults to `http://127.0.0.1:11434`. Without a configured model, utility is marked `skipped`; no quality score is inferred.

## Known methodological limitations

- The synthetic set is small and intentionally pattern-oriented; a strong score is not evidence of real-world recall.
- OpenPII Nano is multilingual and its mapped labels cover only a subset of its annotation taxonomy. The MVP detectors are primarily pattern and checksum based and do not detect names, general locations, dates or arbitrary identifiers unless optional NER/custom rules are enabled.
- Presidio defaults may depend on language-model packages not installed by this project. If its default Analyzer cannot initialize, that comparator is skipped and the reason class is recorded.
- Exact-span scoring treats all mapped entities equally and does not score confidence calibration, severity, masking utility or privacy risk.
- The Ollama task set is tiny and the term-match rubric can miss semantically equivalent answers or reward incomplete ones. It is not a substitute for blinded human evaluation.
